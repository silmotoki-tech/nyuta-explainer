# ライブラリ (nyuta-explainer)

院内の資料PDFを、iPadでタップして選んで開くためのアプリ。飼い主様への説明に紙芝居のように使うほか、スタッフが診療中に調べものをする用途も兼ねる。

## 構成

- React + Vite + Tailwind CSS v4
- Firebase Firestore（メタデータ）+ Firebase Storage（PDF・サムネイル本体）
- pdf.js（PDF表示・サムネイル生成）
- @dnd-kit（編集モードでのドラッグ&ドロップ並び替え）
- vite-plugin-pwa（ホーム画面追加・キャッシュ高速化）

閲覧は誰でもオープン。追加・編集・並び替えは、編集モード（6桁PINで開く）に入っているときだけ操作できる。書き込みは院内共通アカウントでの自動サインインにひもづけて保護している。

## ① Firebaseプロジェクトの準備（ブラウザでの一度きりの作業）

1. https://console.firebase.google.com/ を開き、いつも使っているアカウント（Blazeプラン）で新規プロジェクトを作成する。
2. 左メニュー「Firestore Database」→ データベースを作成（本番モード、リージョンは他のクリニックアプリと同じものを選ぶと良い）。
3. 左メニュー「Storage」→ 開始する（デフォルト設定でOK）。
4. 左メニュー「Authentication」→ Sign-in method で「メール/パスワード」を有効化 → Users タブで院内共通アカウント（例: `staff@nyuta-ahp.com` のような、実在しなくてもよい専用メールアドレス＋任意のパスワード）を1つ作成する。これが `.env` の `VITE_SHARED_ACCOUNT_EMAIL` / `VITE_SHARED_ACCOUNT_PASSWORD` になる。
5. Firestore の「ルール」タブに、このリポジトリの `firestore.rules` の内容を貼り付けて公開する。（資料は `categories/{categoryId}/materials` というサブコレクションに保存する構成にしている。複合インデックスが不要になるための設計。）
6. Storage の「ルール」タブに、このリポジトリの `storage.rules` の内容を貼り付けて公開する。
7. 「プロジェクトの設定」→「全般」→ 一番下の「マイアプリ」でウェブアプリを追加し、表示される設定値（apiKey, authDomain, projectId, storageBucket, messagingSenderId, appId）を控える。

## ② Firestoreの初期データ（カテゴリ）を登録する

Firestore の「データ」タブから、`categories` コレクションを作成し、以下の3件のドキュメントを追加する（ドキュメントIDは自動採番でよい）。

| name | order | icon |
| --- | --- | --- |
| インフォーム資料 | 0 | 🩺 |
| 飼い主様資料 | 1 | 🏠 |
| 診療資料 | 2 | 📚 |

最上位のカテゴリを増やしたくなったら、同じ要領でドキュメントを1件追加するだけでよい（コードの変更は不要）。

### カテゴリの入れ子（フォルダ）

カテゴリは `parentId`（親カテゴリのドキュメントID）を持たせることで入れ子にできる。ホーム画面には `parentId` を持たないものだけが並び、下位フォルダを持つカテゴリを開くとフォルダ一覧が表示される。

診療科ごとのフォルダのような下位フォルダは、**アプリの編集モードから「＋ フォルダを追加」で作れる**ので、通常はFirestoreを直接触る必要はない。`order` は同じ親を持つ兄弟の中での並び順で、追加した順に振られる。

フォルダの削除は、中に資料も下位フォルダも入っていないときだけ許可している（サブコレクションの資料が取り残されるのを防ぐため）。

### 表示形式（layout）

カテゴリに `layout: 'list'` を持たせると、4列のアイコン帯ではなく**50音順のテキスト一覧**で表示される。薬剤情報のように品目が多く、アイコンより名前で探すカテゴリ用。`layout` を持たないカテゴリはこれまでどおりアイコン帯。

リスト表示では次のように振る舞う。

- 下位フォルダと直下の資料を**混ぜて**50音順に並べる。資料が1つしかない薬剤はフォルダを作らずPDFを直接置けば1タップで開き、複数ある薬剤だけフォルダにできる
- 並べ替えのキーは `reading`（よみ）。カタカナ名なら不要だが、漢字や英字の名前は `reading` を入れないと「その他」に入る
- 上部に検索ボックスと50音ジャンプバーが出る。検索はひらがな／カタカナの違いと英字の大小を無視して照合する
- アイコンは表示しないので、フォルダ作成時もアイコン選択は出ない

`group` を持たせたものは50音の行に混ざらず、**一覧の最後に名前付きの別枠**でまとまる（例: 漢方薬）。50音順に散らばると探しにくい一群を切り出すための仕組み。

数十件をまとめて登録したいときは、フォルダ追加モーダルの「まとめて追加」タブに1行1件で貼り付ける（`名前` / `名前,よみ` / `名前,よみ,グループ`）。既にある名前は飛ばす。

## ③ 環境変数を設定する

`.env.example` を `.env` にコピーし、①②で控えた値を入力する。`VITE_EDIT_PIN` には編集モード用の6桁の数字を設定する。

```
cp .env.example .env
```

## ④ 開発・ビルド

```
npm install
npm run dev      # ローカルで確認
npm run build    # 本番ビルド（dist/ に出力）
```

### テキスト資料（type: 'text'）

PDFのほかに、本文をFirestoreのドキュメントにそのまま持つ資料も置ける。薬剤情報のように、1薬剤1ページで「作用・効果／主な適応／主な副反応／禁忌・注意／モニタリング／参考文献」をまとめて読みたいとき用。Storageを使わないのでアップロードもサムネイル生成も要らない。

- 編集モードの「＋ テキスト」から作る。新規作成時は上記6つの見出しだけが入った状態で作られ、あとから開いて書き足す
- 「まとめて追加」でフォルダと同じ形式（`名前` / `名前,よみ` / `名前,よみ,グループ`）を貼り付ければ、空ページをまとめて用意できる
- 本文は簡易記法。`## 見出し` `### 小見出し` `- 箇条書き` と、URLの自動リンクだけ解釈する（ライブラリは足していない）
- **本文の印刷は用意していない。** 画面で参照する用途のため。PDFのA4整形と違い、テキストからのPDF生成は日本語フォントの埋め込みが必要で別作業になる

#### 関連資料（テキスト資料にぶら下げるPDF）

薬剤の添付文書のように「その薬剤についてのPDF」は、資料として別に置かず、テキスト資料のページ下部の「関連資料」に足す。編集モードで開いて「＋ PDFを追加」。

- 一覧（50音リスト）には**薬剤名が1行並ぶだけ**で、PDFが薬剤名の隣に別項目として混ざらない。1タップで開いた先に本文もPDFも揃う
- `materials/{categoryId}/{materialId}/{uuid}.pdf` に保存し、親ドキュメントの `attachments: [{ id, title, storagePath, fileUrl }]` に持たせる（Storageのルールは `materials/**` のままで足りる）
- タップすると通常のPDFビューアが上に重なって開く。**A4整形も印刷（共有シート）もそのまま効く**
- サムネイルは作らない（一覧に並ばないため）。資料本体を削除すると関連資料のファイルも一緒に消える

## ⑤ 資料の形式ルール

**ファイルとして登録する資料はPDFで書き出す。** アプリが受け付けるファイルもPDFのみ（`accept="application/pdf"`）。テキスト資料は別枠（上記）で、ファイルを伴わない。

画像（PNG等）を受け付けない理由は印刷品質にある。飼い主様にお渡しするA4の紙をきれいに印刷するには 2480×3508px（300dpi）必要で、最低ラインでも 1240×1754px（150dpi）。CanvaやスライドツールのPNG書き出しは既定で横1080px程度しかなく、A4に引き伸ばすと100dpi弱になって文字がにじむ。PDFなら文字が文字のまま残るので、どの大きさで印刷しても輪郭が保たれる。

Canva・Googleスライド・Word・PowerPointはいずれもPDF書き出しが1クリックでできる。受け入れ形式を増やすより、書き出し形式を統一するほうが品質のバラつきを防げる、という判断。

将来どうしても画像を扱う必要が出たら、`materials` の `type` フィールド（現在は `'pdf'` 固定）で分岐させる想定。その際はアップロード時に解像度が足りない画像を警告する仕組みも一緒に入れること。

## ⑥ iPadでの運用メモ

- 各iPadでSafariからアプリを開き、共有ボタン→「ホーム画面に追加」しておくと、アドレスバーのない専用アプリのような見た目で使える。
- 飼い主様に端末を渡すときは、渡す前に本体側面（またはホーム）ボタンを3回押して「アクセスガイド」を開始する。終了時は同じ操作＋設定したパスコード（6桁）で解除する。設定は「設定 > アクセシビリティ > アクセスガイド」から行う。
- Wi-Fiが安定している前提でオンライン動作。一度開いた資料はキャッシュされるため、2回目以降は高速に開く。
